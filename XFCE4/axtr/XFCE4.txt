### Resumo do que o script faz:

1. **Atualiza** o sistema com `apt update`
2. **Instala** pacotes: XFCE4 (ambiente gráfico), noVNC, Websockify, TightVNC Server, htop, nano, neofetch e Firefox
3. **Gera** um certificado SSL autoassinado (`novnc.pem`) válido por ~10 anos
4. **Configura** o VNC Server:
   - Mata a sessão existente (`vncserver -kill :1`)
   - Faz backup do `xstartup` original
   - Edita o `xstartup` para iniciar o XFCE4
   - Reinicia o VNC Server
5. **Inicia** o noVNC via Websockify na porta **6080**, redirecionando para o VNC na porta **5901**, usando o certificado SSL gerado

> ⚠️ **Nota:** Há um possível erro no comando `openssl` — o parâmetro `-x509` parece estar escrito como `-x500` na imagem, e `rsa:3072` parece estar como `rsa:3072` (ou possivelmente `rsa:3072`). Verifique antes de executar.

# Como Ligar o Servidor Novamente

Depende do que você quer dizer com "desligar":

## 1️ Se você desligou a **máquina/instância** (VPS, AWS, etc.)

### Via Painel Web (mais comum):
- **AWS EC2:** Acesse o Console AWS → EC2 → Instâncias → Selecione → Actions → Start
- **Google Cloud:** Console GCP → Compute Engine → VM Instances → Clique em "Iniciar"
- **Azure:** Portal Azure → Virtual Machines → Selecione → Start
- **DigitalOcean/Vultr/Linode:** Painel web → Droplet/Instance → Power On

### Via linha de comando (se tiver outra máquina acessível):
```bash
# AWS (usando AWS CLI)
aws ec2 start-instances --instance-ids i-SEU_ID

# Google Cloud
gcloud compute instances start NOME_DA_INSTANCIA

# Azure
az vm start --resource-group GRUPO --name NOME_DA_VM
```

---

## 2️⃣ Se a máquina está ligada, mas os **serviços VNC/noVNC pararam**

Crie um script para reiniciar tudo rapidamente:

```bash
#!/bin/bash
# Salve como: ~/iniciar-vnc.sh

# Matar sessões antigas
vncserver -kill :1 2>/dev/null

# Iniciar VNC Server
USER=root vncserver

# Iniciar noVNC
websockify -D --web=/usr/share/novnc/ --cert=/root/novnc.pem 6080 localhost:5901

echo "VNC e noVNC iniciados!"
echo "Acesse: https://SEU_IP:6080/vnc.html"
```

**Dar permissão e executar:**
```bash
chmod +x ~/iniciar-vnc.sh
~/iniciar-vnc.sh
```

---

## 3️⃣ Para iniciar automaticamente ao ligar a máquina

Crie um serviço systemd:

```bash
sudo nano /etc/systemd/system/vnc.service
```

**Conteúdo do arquivo:**
```ini
[Unit]
Description=VNC Server com noVNC
After=network.target

[Service]
Type=forking
User=root
ExecStartPre=/usr/bin/vncserver -kill :1
ExecStart=/usr/bin/vncserver :1
ExecStop=/usr/bin/vncserver -kill :1
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

```bash
sudo nano /etc/systemd/system/novnc.service
```

**Conteúdo do arquivo:**
```ini
[Unit]
Description=noVNC Web Interface
After=vnc.service
Requires=vnc.service

[Service]
Type=forking
User=root
ExecStart=/usr/bin/websockify -D --web=/usr/share/novnc/ --cert=/root/novnc.pem 6080 localhost:5901
ExecStop=/usr/bin/pkill -f websockify
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

**Ativar os serviços:**
```bash
sudo systemctl daemon-reload
sudo systemctl enable vnc.service
sudo systemctl enable novnc.service
sudo systemctl start vnc.service
sudo systemctl start novnc.service
```

Agora, sempre que a máquina ligar, o VNC e noVNC iniciarão automaticamente! ✅

# Erro: `Address already in use` (Porta 6080 já em uso)

O erro indica que **a porta 6080 já está sendo usada** por outro processo (provavelmente uma instância anterior do websockify que não foi fechada corretamente).

---

## 🔧 Solução 1: Matar o processo que está usando a porta 6080

```bash
# Ver qual processo está usando a porta 6080
sudo lsof -i :6080
# ou
sudo netstat -tlnp | grep 6080
# ou
sudo fuser -v 6080/tcp
```

**Matar o processo:**
```bash
sudo fuser -k 6080/tcp
```

**Depois, rode o comando novamente:**
```bash
websockify -D --web=/usr/share/novnc/ --cert=/home/ubuntu/novnc.pem 6080 localhost:5901
```

---

## 🔧 Solução 2: Matar todos os processos websockify

```bash
sudo pkill -f websockify
```

Depois reinicie:
```bash
websockify -D --web=/usr/share/novnc/ --cert=/home/ubuntu/novnc.pem 6080 localhost:5901
```

---

## ⚠️ Outro problema detectado na imagem!

Olhando a saída do websockify, aparece:

```
- No SSL/TLS support (no cert file)
```

Isso significa que o certificado **NÃO foi carregado**. O caminho `/home/ubuntu/novnc.pem` provavelmente **não existe** porque você está logado como `root`, não como `ubuntu`.

### Verifique onde o certificado está:
```bash
find / -name "novnc.pem" 2>/dev/null
```

### Corrija o caminho no comando:
```bash
# Se o certificado está em /root/
websockify -D --web=/usr/share/novnc/ --cert=/root/novnc.pem 6080 localhost:5901

# Ou se está no diretório atual
websockify -D --web=/usr/share/novnc/ --cert=./novnc.pem 6080 localhost:5901
```

---

## 📋 Passo a passo completo para resolver:

```bash
# 1. Matar processos websockify existentes
sudo pkill -f websockify

# 2. Verificar se a porta 6080 está livre
sudo lsof -i :6080

# 3. Localizar o certificado novnc.pem
find / -name "novnc.pem" 2>/dev/null

# 4. Iniciar o websockify com o caminho correto do certificado
websockify -D --web=/usr/share/novnc/ --cert=/root/novnc.pem 6080 localhost:5901

# 5. Verificar se está rodando
sudo lsof -i :6080
```

## 💡 Dica: Script para reiniciar tudo limpo

```bash
#!/bin/bash
echo "Parando serviços..."
vncserver -kill :1 2>/dev/null
pkill -f websockify 2>/dev/null
sleep 2

echo "Iniciando VNC Server..."
USER=root vncserver :1

echo "Iniciando noVNC..."
websockify -D --web=/usr/share/novnc/ --cert=/root/novnc.pem 6080 localhost:5901

echo "Pronto! Acesse: https://SEU_IP:6080/vnc.html"
```

Salve como `~/restart-vnc.sh`, dê permissão com `chmod +x ~/restart-vnc.sh` e execute sempre que precisar reiniciar. ✅
